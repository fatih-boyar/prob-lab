If not purely random, than reliable?

A perfect example of an NHST fallacy
NHST
statistics
Published

February 9, 2026

Modified

February 10, 2026

Here is a perfect example of an NHST fallacy that I encountered. I had to read an old paper from 1988 (Zimmer and Golden 1988) about content analysis of consumer images for one of my PhD courses “Research Methods”. Often, when you read literature from that era, it is a classic, and still relevant, therefore you encounter a great work. However, that is not the case here. An outdated textbook was used for the course throughout the years, and many papers simply remained in the corpus.

In the paper, authors try to find the “images” of retail stores. They literally ask: “Please describe your image of ________ (store name)”. Kinda funny when you put it in this way, but before that studies involved differential scales such as interesting vs. boring, or strong vs. weak etc. So at that time, asking the image directly provided more and nuanced data. Anyway, when you ask in an unsutructured way, the effort lies on inferring themes or categories from those answers people gave about images. Skipping the details, the authors refined the data to 220 themes and then to 47 categories. The 3 judges (assistants) were brought in after the categories were created to test if the categories made sense. These 3 judges also did the same thing, reduced 220 themes into 47 categories and then they compared the results of these judges to see how similar the outcome was, therefore provide reliability of this categorization. Showing that it is not just subjective decisions of authors but a generalizable logic. The results are in the table.

The logic in calculating reliability is simply asking this:

“How extreme would it be for two judges to make so many identical choices, assuming the choices were completely random?”

Because it is binary, it follows binomial distribution. Let’s see A and B. They made the same choice 40% of the time. Oh my, this is so extreme, therefore they were not doing this randomly, they are up to something!

Well, in this example its clear that both the question and the logic is silly. First, they are of course not choosing the categories randomly. Second, we see the infamous illegal logic flip right there: “If it is too extreme, then it can’t be random.” Jumping from rejecting the null hypothesis (randomly choosing) to conferring the categorisation is reliable.

The probability of matching 90 out of 220 (given that the choices were random) is extremely small. But check the calculation below, even if the matches were only 11, the probability is 0.005, falling way below the generally acceptable p-values (would get three nice stars *** because p<0.01). Does this mean that even if 11 matches out of 220 would mean that the study achieved reliability?

def server(input, output, session):
    
    @reactive.Calc
    def p_val():
        try:
            val = eval(input.p_str(), {"__builtins__": None}, {})
            if not isinstance(val, (int, float)) or val < 0 or val > 1:
                return None
            return float(val)
        except Exception:
            return None

    @render.text
    def result_val():
        n = input.n()
        x = input.x()
        p = p_val()
        
        if p is None or n is None or x is None: 
            return "Err"
        
        type_ = input.type()
        
        if type_ == "eq":
            prob = binom.pmf(x, n, p)
        elif type_ == "lte":
            prob = binom.cdf(x, n, p)
        else: # gte
            prob = 1 - binom.cdf(x - 1, n, p)
            
        if 0 < prob < 0.0001:
            return f"{prob:.4e}"
        return f"{prob:.5f}"

    @render.plot
    def dist_plot():
        n = input.n()
        p = p_val()
        target_x = input.x()
        
        if p is None or n is None: return None

        # Calculate plotting range (mean +/- 4 SD)
        mean = n * p
        sd = np.sqrt(n * p * (1 - p))
        
        low = max(0, int(np.floor(mean - 4 * sd)))
        high = min(n, int(np.ceil(mean + 6 * sd)))
        
        # If the range is too narrow (e.g. n=1), force a small window
        if high - low < 5: 
            high = low + 10
            
        x_vals = np.arange(low, high + 1)
        y_vals = binom.pmf(x_vals, n, p)
        
        fig, ax = plt.subplots()
        
        # Plot bars
        bars = ax.bar(x_vals, y_vals, color="#6495ED", width=0.6, align='center')
        
        # Highlight specific x
        if target_x is not None and low <= target_x <= high:
            idx = np.where(x_vals == target_x)[0]
            if len(idx) > 0:
                bars[idx[0]].set_color("#e8586d")

        # Clean up styling
        ax.set_ylabel("P(X=x)")
        ax.set_xlabel("x")
        
        # Remove top/right spines for cleaner look
        ax.spines['top'].set_visible(False)
        ax.spines['right'].set_visible(False)
        ax.spines['left'].set_visible(False) # Optional: cleaner look
        
        plt.tight_layout()
        return fig

app = App(app_ui, server)

The literature has improved on this reliability issue and better methods have been suggested, but the fundamental logic of NHST persists. During the lecture, I suggested using priors and Beta distributions, arguing that we need to incorporate prior information. We can model judges’ category choices not as completely random, but as coming from a common Beta distribution where some categories naturally have higher probability. It sounded esoteric in the class at the time, but I believe that’s where the nuance of human judgment lies.
